Build 1 — Create your file-native agent

Model: Sonnet · Time: 10 min

Set up the agent's operating-system folder directly on your computer — the simplest option, and the only one that supports /loop (proactive scheduled runs).

Steps:

Create a new folder anywhere on your computer, named after the agent, lowercase with dashes (e.g., athena-agent).

Open Claude Code (desktop app) → Open Folder → select the new folder; confirm it's loaded as the working directory (folder name shows in the top bar).

Run the file-structure prompt in that session.

Reusable prompt — scaffold the agentic OS structure:

Goal: I want to setup my agentic OS file structure in this folder.

Context: The file structure for this agentic OS is the optimized structure for making you as an agent intelligent.

Rules: Create these folders and files in this exact structure:

[FolderName]/

├── CLAUDE.md ← operating system kernel (soul, routing, dispatch)

│

└── .claude/

├── agents/ ← subagent definitions

├── skills/ ← slash command library

└── settings.json/ ← hard rules



Note: because this folder lives on your computer, cloud-hosted agents (Claude cloud sessions, Codex) can't access it — any work here needs your computer open and Claude Code running. The tradeoff is /loop support (Build 5).

Alternate paths offered: GitHub-hosted OS; Codex.

Build 2 — Write your agent's identity file

Model: Sonnet · Time: 25 min

Build CLAUDE.md (loaded every session) through a structured interview covering identity, user profile, tools, routing rules, and a memory pointer — then add a humanize-output skill and a hook that guarantees its routing rule actually fires.

Steps:

Run the identity-interview prompt (max 6 questions) to generate the CLAUDE.md skeleton: Soul, User Profile, Routing Rules (placeholder), Tools Connected (placeholder), Memory Pointer.

Upload a couple of your own writing samples (not AI-generated) and run the humanize-output skill-creation prompt via /skill-creator — or reuse/improve a Level 1 humanize skill if you have one.

Add a hard-rule routing entry to CLAUDE.md: any output seen/sent/published by someone else must run through humanize-output first (internal reasoning and tool calls exempt).

Create a UserPromptSubmit hook in .claude/settings.json that scans incoming messages for trigger words ("write," "draft," "create," "document," "message," "report," "send") and injects a reminder to re-read the routing rule before responding.

Test in a new session by asking the agent to draft a message — confirm the hook fires and humanize-output is applied.

Reusable prompt — identity interview:

Goal: Define and write a job description for you as my Chief of Staff agent. Document processes that are done regularly and could be done by you as the agent.

Context: I want to brainstorm conversationally with you to decide:

1. Document processes I do every day, what good looks like

2. Which processes are easy to write instructions for a machine to do them instead of myself

You will definitely own jobs like research and project management and some communications so make sure to ask me about that to find machine ready processes. You are synthesizing all of our brainstorming to create a CLAUDE.md identity file.

Rules: Ask no more than 6 questions. Fill out the CLAUDE.md in this repo with this format:

# [Agent name] - Chief of Staff

## 1. Soul

[Personality, tone, how it communicates, what it never says, how it pushes back. The jobs it owns. What good output looks like. When to ask vs. act.]

## 2. User Profile

[Who I am, how I work, what I prioritize, what I consider a waste of time, the people and tools that matter most in my week. timezone]

## 3. Routing Rules [Placeholder Section for now]

## 4. Tools Connected [Placeholder Section for now]

## 5. Memory Pointer

[→ /memory for referencing previous knowledge or patterns found]



Reusable prompt — build humanize-output skill:

Goal: Create a skill named humanize-output that humanizes any AI output.

Context: Use the /skill-creator skill and the example files I just attached that show my own grammar and tone and have some context for the type of work that I do. I want it to humanize output in a way that mirrors exactly the grammar and tone the way that I write.

Rules: Include good examples and bad examples in the skill file so that there is a good way for me to fine-tune this skill



Reusable prompt — add the humanize routing rule:

Add a routing rule to the routing section of my CLAUDE.md that says: any output that will be seen, sent, or published by someone else must be run through the humanize-output skill before being returned. This includes drafts, messages, reports, documents, and any text that leaves this agent. Internal reasoning and tool calls are exempt. Label it as a hard rule.



Reusable prompt — add the enforcement hook:

Create a UserPromptSubmit hook in my project's .claude/settings.json that scans each incoming message for words like "write," "draft," "create," "document," "message," "report," or "send." If any match, inject a reminder that tells the agent to re-read the humanize-output routing rule in CLAUDE.md before responding. Keep the hook command short and use the CLAUDE.md path relative to the project root.



Reusable prompt — test the hook:

Draft a short message to my team about the hook I set up for my chief of staff agent. Explain what hooks are and why they are important.



Go further: work with an agent to improve CLAUDE.md.

Build 3 — Build your agent's kanban board

Model: Sonnet · Time: 15 min

Give the agent a persistent working surface (a Notion kanban board, chosen for the richest MCP read/write access) that survives past any single session — it reads at startup and writes on completion.

Alternate surfaces to Notion: tasks.md in the folder (no setup needed); a single-file HTML board; Linear/Asana/Trello via their own MCP servers. Mental model is the same regardless.

Steps:

Confirm the Notion MCP is active by asking Claude directly whether it can access the workspace.

Have Claude build the full board via the board-creation prompt — verifying board view, column order, and 3 starter cards before finishing.

Wire the board into CLAUDE.md and add two UserPromptSubmit hooks (query phrases → briefing; add-task phrases → new Inbox/Backlog card) via the wiring prompt.

Test by starting a new session and asking "what's on my kanban board?" — confirm the agent pulls Today/In Progress and asks about promoting backlog items.

Reusable prompt — check Notion access:

Do you have access to my Notion workspace?



Reusable prompt — build the Notion Kanban board:

Goal: Create a Notion Kanban board for tracking agent tasks.

Context:

- Use the Notion MCP

- Database name: "Agent Kanban"

- Status property options in order: Inbox/Backlog, Today, In Progress, Blocked, Done

- Notes text property

- Default view: Board, grouped by Status, columns in that left-to-right order

- 3 starter task cards in Inbox/Backlog pulled from CLAUDE.md

Rules:

- Verify the default view is Board before finishing

- Verify columns are in the correct order before finishing

- Verify the 3 task cards exist in Inbox/Backlog before finishing

- Fix anything wrong before moving on



Reusable prompt — wire the board into agent behavior:

Goal: Wire the Agent Kanban board into the agent's behavior.

Context:

- Add the Agent Kanban database URL to CLAUDE.md

- Create two UserPromptSubmit hooks in .claude/settings.json:

1. Matcher for kanban query phrases ("what's on my board", "what do I need to do today", "what's on my kanban", "show my tasks"): call the Notion MCP, pull Today and In Progress cards, report as a briefing, then surface Inbox/Backlog and ask if anything should move up

2. Matcher for add-task phrases ("add this to my kanban", "add this task", "track this"): call the Notion MCP and create a new Inbox/Backlog card from the task name in the message

Rules:

- Add routing rules to CLAUDE.md for both behaviors

- Test the query hook: send "what do I need to do today?" and confirm the briefing shows up and the Inbox/Backlog question gets asked

- Test the add-task hook: send a trigger phrase and confirm a card appears in Notion

- Save to .claude/settings.json so hooks are scoped to this project only

Build 4 — Delegate a work task to your agent from your phone

Model: Sonnet · Time: 15 min

Use Dispatch (Cowork on the local machine) to hand a task to the local agent OS from your phone.

Steps:

On Claude Desktop: Cowork sidebar → Dispatch, complete any setup. On the Claude mobile app: open the Dispatch tab.

Paste a Dispatch prompt naming the exact project folder and asking it to add a new kanban task.

Verify the task appeared in Notion; send a follow-up Dispatch prompt telling the same session to actually run the task (check communications); confirm it completes and the card moves to Done.

Reusable prompt — dispatch a new kanban task:

Start a new Claude Code session in the Project folder [Your Project name] And use that Claude Code session to create a new task in my Kanban board that is to catch up on all my work communications. Update me on anything the Claude Code session returns, such as kanban board updates etc.



Build 5 — Make your agent proactive

Model: Sonnet · Time: 15 min

Give the agent a heartbeat via /loop — a recurring cycle that observes communications and work repos, reasons about changes, updates the kanban board, and writes a memory summary for the next cycle, entirely without a human in the loop.

Steps:

Create a private Slack channel for agent updates (Slack desktop → Directories → Channels → Create Channel → name it e.g. [agent-name]-messages → Private).

Ensure at least 3 tasks exist on the agent kanban board.

In a local Claude Code session with the agent OS folder open, run the /loop 20m heartbeat prompt, filling in real communication channels and work repositories.

Check the kanban board for new/updated cards; try completing a couple of tasks before the next heartbeat to confirm the loop reacts correctly.

Reusable prompt — heartbeat loop:

/loop 20m

**Goal**

Run a heartbeat cycle on my kanban board. Each cycle: observe my communications and work repositories, reason about what has changed, decide what to update or create, and reflect by writing a summary to memory so the next cycle has context.

**Observe**

Pull fresh data from COMMUNICATION CHANNELS:[fill in list] (e.g. Slack, Gmail, Google Calendar) and WORK REPOSITORIES:[fill in list] (e.g. Notion, Google Drive, GitHub).

**Reason**

- What tasks have been assigned to me since the last cycle?

- What cards have new progress or status changes?

- What cards are missing their source communication link?

- Are any linked communications showing a green check mark reaction?

**Decide**

- Update any card whose status has changed based on what you found

- Attach the source communication link to any card missing one

- Move any card to Done if its linked communication has a green check mark reaction

- Create a new card for any assigned task not already on the board

- Never pull status from manual card edits, only from [COMMUNICATION CHANNELS] and [WORK REPOSITORIES]

- No duplicate cards; update existing ones

**Reflect**

Write a short summary to memory: what you observed, what changed, and what actions you took. The next cycle should start by reading this summary before pulling fresh data.



Note: loops auto-expire 7 days after creation — restart a new loop weekly to keep the heartbeat running.

Go further: sync the GitHub repository on a schedule.
