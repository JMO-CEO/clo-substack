Build 1 — Build or improve your AI context file

Model: Sonnet · Time: 18 min

Create a root CLAUDE.md — persistent context every future build in the program draws on.

Steps:

Open a new Claude Code session (folder doesn't matter yet) and run the interview prompt in auto mode with Sonnet.

Once saved and moved to ~/.claude/CLAUDE.md, ask Claude to review it for gaps, then iterate — clarify or add anything missing, contradictory, or too vague to act on.

Reusable prompt — build root CLAUDE.md:

Goal: Build my root CLAUDE.md from scratch and save it to ~/.claude/CLAUDE.md.

Context: Read everything in my ~/.claude/ folder first - skills, context files, notes - so you know what I've already built.

Rules:

- Fill in what you can infer from my folder; interview me one question at a time for the rest

- Cover: my role and day-to-day work, top goal, what a successful quarter looks like, what I'd cut from my week, and what tools are connected (check /mcp or my connectors)

- Include a How I Work section with these principles (adjust based on what you learn about me): enter plan mode for any 3+ step task or architectural decision; STOP and re-plan if something goes sideways; use subagents to keep the main context clean; after any correction write a rule to prevent the same mistake; never mark complete without showing output first; ask "is there a more elegant way?" before non-trivial delivery; simplicity first; no temporary fixes

- When I've answered everything, write the complete file, save it to the working directory, and give me instructions to move it to ~/.claude/



Reusable prompt — review CLAUDE.md for gaps:

Goal: Review my CLAUDE.md and identify gaps.

Rules:

- Flag anything missing, contradictory, or too vague to act on

- Tell me what you still wouldn't know about me after reading it



Share: post the CLAUDE.md rule expected to save the most time in cohort Slack.

Build 2 — Audit your time and generate automation ideas

Model: Sonnet · Time: 22 min

Run a time audit that reads real data (app usage, browser history, calendar, optionally email/Slack) and surfaces automations tied to your goals.

Steps:

Create a my-agents folder (somewhere memorable — home directory or Documents). This becomes the working folder for all of Level 2; move any Level 1 ai-builder folder into it.

Open Claude Code with my-agents selected as the working folder each session going forward.

Grant data-source access: Mac — System Settings → Privacy & Security → Full Disk Access → enable both Claude entries (desktop app and CLI); Windows — Settings → Privacy & Security → Activity History → "Store my activity history" on, then restart the desktop app after granting Full Disk Access. Browser history is read automatically. Confirm calendar access by asking Claude directly whether it can see your Google Calendar. Data stays private and read-only except for the generated time-audit.html file, and Claude Code asks for approval before creating/changing anything.

Run the time-audit prompt (Mac or Windows variant) in a new Sonnet session — it asks 3 quick questions (data sources, lookback window, what the audit should answer) with sensible defaults, then builds and saves time-audit.html with fixed section headings, followed by an optional Phase 2 for email/Slack.

Open time-audit.html in a browser and review the time breakdown and automation opportunities.

Reusable prompt — time audit (Mac):

Goal: Run a work analysis and save the output as time-audit.html in my working directory.

Context: Read my CLAUDE.md first and use my goals, role, and priorities as the lens throughout. Work entirely in this session - never use the Task tool or spawn subagents, and never run any git commands. Small scripts in the main session are faster here than parallel agents.

Step 1 - ask me these three questions in one message, then stop and wait for one reply. Tell me I can answer "defaults" to take all three and start immediately. Ask nothing else: no follow-ups, no confirmation round.

1. Which sources? (a) Mac app usage (b) Chrome/Safari history (c) Google Calendar (d) Email (e) Slack - default: a, b, c

2. How far back? - default: last 10 weekdays, 8am-6:30pm

3. What should this audit help me figure out? e.g. "I'm in too many meetings", "what should I automate first" - default: measure my time against my #1 goal

Phase 1 - build the core report from the sources I picked:

- Write one Python script that pulls the local sources I picked in a single pass: Mac app usage (copy ~/Library/Application Support/Knowledge/knowledgeC.db to /tmp/knowledgeC.db first) and Chrome history (find the correct profile by work email in Local State; fallback to Safari). Wrap each source in its own try/except - catch, print, continue - so one run surfaces every problem at once. Print results as JSON and read that for the analysis. On error patch only the failing function, never the whole script; if a source fails twice, mark it unavailable and move on

- For Mac app usage: compute all date cutoffs dynamically in Python - never hardcode timestamps; filter to the window I gave you; clean bundle IDs to readable names; aggregate total seconds per app and context switches per day

- For Chrome: copy the locked History DB to temp first (Chrome holds a lock while it's running); open with Python's built-in sqlite3 (no sqlite3 CLI); filter to the window I gave you; group by domain; categorize as comms / AI tools / docs/research / CRM/ops / social / other; flag social media if it exceeds 5% of work-hours visits

- Then pull Google Calendar (skip declined/cancelled/all-day): categorize events as 1:1s (2 attendees), team meetings (3+ internal), external calls (any outside-domain attendee), focus blocks (0 other attendees); report total meeting hours, avg per day, recurring meetings, back-to-back patterns

- Skip anything I didn't pick. If a source I did pick errors or isn't connected: skip it, note it, and keep going. No more than 2 minutes per source. Never stop mid-run to troubleshoot or wait on me

- Synthesize: lead with the question I asked in Step 1 and answer it first, with numbers; then time reality vs. goal alignment; context switching rate; meeting load vs. deep work ratio; top 3 time drains; 2-3 sharp observations naming actual apps, meeting types, domains

- Identify 4-6 automation opportunities ranked by impact (hours reclaimed x goal alignment x relevance to my Step 1 answer). For each: outcome (one sentence), what's happening today, what the automated version looks like, effort label (Quick win / Medium lift / Big build), hours reclaimed per week

- Save time-audit.html now, before anything else. These section headings are fixed, later builds read them by name: header (name, #1 goal, today's date), how I actually spend my time, key diagnostics, goal alignment, automation opportunity cards, data sources used with date ranges (list any skipped or excluded sources), footer

- Style: minimal dark mode - one <style> block, system fonts, no external assets, no animation or gradients, CSS under ~60 lines. A later build restyles this file, so don't invest in polish. Any percentage bars must be display:block (inline spans collapse to zero size). Tell me the path once saved.

Phase 2 - only if I picked email or Slack, and only after time-audit.html is saved:

- Email: pull the same window (sent + inbox), fold reactive vs. proactive patterns into the diagnostics, and update any automation opportunities it changes

- Slack: pull the same window and do the same

- Spend no more than 2 minutes per source. If a pull is slow, errors, or the tool isn't connected, skip it and note it in the file

- Update time-audit.html in place and tell me what changed



Build 3 — Create a design skill

Model: Sonnet · Time: 16 min

Extract a reusable design system from an inspiration site so every HTML deliverable in the course (time audit, dashboard, etc.) looks consistent and unique to you. Done early ("skillify early") because the dashboard build needs it right away.

Steps:

Pick a design-inspiration website (ideally your own company's, if building work deliverables). Use Claude in Chrome (or give the URL directly to your AI tool) to extract the design system.

In Claude in Chrome (Sonnet model), run the extraction prompt against the site; approve any "Allow" prompts.

Copy the resulting design documentation.

Paste it into a new Claude Code session (Sonnet) along with the skill-creation prompt (replacing [site name] with your chosen name) to turn it into a /[site name]-design skill via /skill-creator, saved for use in both Cowork and Chat.

Apply the new skill to time-audit.html and iterate with feedback if needed.

Reusable prompt — extract design system:

Goal: Extract a design system from this page that I can reuse in future prompts.

Context: I'm building a website that should feel like this site.

Rules:

- Extract: primary and accent colors (hex codes if possible), typography style and feel, layout approach, and 5 words that capture the overall vibe

- Format as a structured design system document



Reusable prompt — turn design system into a skill:

Goal: Turn this design system into a reusable skill named [site name]-design.

Rules:

- Use /skill-creator

- Save it so I can use it in both Cowork and Chat

- Skip evals



Go further: create a second design system.

Build 4 — Build your AI automation dashboard

Model: Sonnet · Time: 20 min

Turn the time-audit findings into a prioritized automation list, then vibe-code a Kanban dashboard (ai-builder-dashboard.html) styled with the new design skill.

Steps:

Run the prioritization prompt (same session as the time audit, or a new one with time-audit.html attached) to get a numbered, impact-sorted automation list. Review and push back on anything off before proceeding.

Run the dashboard-build prompt to generate ai-builder-dashboard.html: a 4-column Kanban (Suggested / To Build / In Progress / Done), drag-and-drop with localStorage persistence, a "View Time Audit" popup pulling key sections from time-audit.html, and the design skill's palette/font applied.

Start a local server to preview the dashboard reliably (drag-and-drop state needs a served origin, not a raw file open) and confirm state persists across a tab close/reopen.

Reusable prompt — generate automation priorities:

Goal: Give me a prioritized list of specific things I could automate or hand off to AI.

Context: Read time-audit.html first.

Rules:

- Numbered list, sorted by impact (highest first)

- For each item: what it is (one line), why it's worth automating (time saved or friction removed), rough effort (Quick win / Medium lift / Big build)



Reusable prompt — build the Kanban dashboard:

Goal: Build ai-builder-dashboard.html - a kanban board for my automation roadmap - and save it to my working directory.

Context: Use the automation ideas from our conversation as the starting cards. Read my CLAUDE.md for my name and #1 goal. Read time-audit.html for the 3 most important insights.

Rules:

- Top section (scrolls, not frozen): my name, my #1 goal, 3 key insights from the time audit

- Four columns: Suggested / To Build / In Progress / Done

- Suggested column has an "Add card" button for new ideas

- All automation ideas from our conversation start in "To Build"

- Each card: name, one-line description, effort label (Quick win / Medium lift / Big build)

- Drag-and-drop between columns; state persists in localStorage

- "View Time Audit" link opens a popup (not a new tab) showing the "How I actually spend my time" and "Key diagnostics" sections from time-audit.html, with a close button

- Check ~/.claude/skills/ for a [style]-design skill file and apply that palette and font; if not found, check this working directory for any file with "design" in the name

- Save the file and tell me the path



Reusable prompt — local preview server:

Goal: Start a local server so I can preview ai-builder-dashboard.html in the browser.

Rules:

- Use Python's built-in HTTP server or npx serve - whichever works on my machine

- Point it at my working directory and give me the exact URL to open



Go further: add the dashboard to CLAUDE.md; bring it to life with animations; connect a Notion backend.

Build 5 — Host your dashboard on Vercel

Model: Sonnet · Time: 12 min

Deploy the dashboard to a permanent, shareable public URL (free Hobby plan, no credit card).

Steps:

Create a free Vercel account at vercel.com.

In Claude Code, from the folder holding ai-builder-dashboard.html, run the deploy prompt — it installs the Vercel CLI if missing, signs you in (waits for browser login), deploys the folder as a static site with the dashboard at the root URL, and reports the live production URL.

Test the live site in a new tab and on your phone; confirm drag-and-drop still works.

Ship future updates any time with vercel --prod — replaces the same URL within seconds.

Reusable prompt — deploy to Vercel:

Goal: Host ai-builder-dashboard.html on Vercel and give me the live URL.

Rules:

- Check for the Vercel CLI (run vercel --version); if it's missing, install it with npm i -g vercel

- Run vercel login if I'm not already signed in - a browser window will open; wait for me to finish before continuing

- Deploy this folder as a static site and make ai-builder-dashboard.html the page that loads at the root URL

- Run the production deploy (vercel --prod) and report the live URL

- If the deploy fails because the Vercel CLI is out of date, upgrade it and retry


