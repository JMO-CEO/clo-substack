Build 1 — Connect your tools (Slack + Gmail)

Model: Sonnet (Haiku for the Slack test) · Time: 15 min

Connect Slack and Gmail via Claude Code's /mcp connector so it can read, summarize, and draft on your behalf.

Steps:

In Claude Code, type /mcp, choose Slack, select Authenticate, confirm the AI Builder workspace is selected in the browser auth screen, click Allow, then re-run /mcp to confirm it's connected.

Set model to Haiku (/model) and run the Slack connection test.

Type /mcp, choose Gmail, select Authenticate, sign in with work or personal Gmail.

Set model to Sonnet (/model) and run the Gmail connection test.

Confirm Claude Code returns real emails and reasonable draft replies before moving to Build 2.

Build 2 — Create your email voice guide

Model: Sonnet · Time: 20 min

Build a humanize-writing skill so Claude Code writes in your voice instead of sounding like generic AI, grounded in an email-voice-guide generated from your own sent emails.

Steps:

Download the humanize-writing skill file into the ai-builder folder.

Install it as a skill in ~/.claude/skills/.

Set model to Sonnet and run the email-voice-guide build prompt (pulls 20 most recent sent emails, excludes automated replies/invites/one-liners, produces an 8-section email-voice-guide.md).

Review the guide; correct inline or direct Claude Code to adjust; save as email-voice-guide.md in ai-builder.

Paste the guide into the humanize-writing skill's ## Email Voice Guide section (replacing the placeholder note only).

Test by asking Claude Code to draft a quick email and checking it sounds like you.

Reusable prompt — install humanize-writing skill:

I downloaded humanize-writing.md into this folder. Install it as a skill in ~/.claude/skills/ so I can use it in any session, then confirm it's available.



Reusable prompt — build email voice guide (8-section spec):

Goal: I want to build an email voice guide that will allow you to draft emails that sound like me

Rules: Pull my 20 most recent sent emails. Exclude automated replies, calendar invites, and one-liners under 3 sentences. Use what remains as my writing corpus.

Analyze those emails and build an email-voice-guide.md with the following 8 sections. Every example must come from my actual emails - no fabricated quotes. Keep it dense and specific to me. No generic writing advice.

1. Core Identity (~150 words)

The 3-4 beliefs that shape how I write emails. Not personality traits - what do I assume about the reader? What do I think email is for?

2. Registers (~300 words)

How my tone shifts across email types: cold outreach, internal updates, follow-ups, feedback, and casual check-ins. Include one real quote from each type found in my emails.

3. Sentence-Level Patterns (~150 words)

Default sentence length, use of fragments, paragraph structure, punctuation habits, and how I handle line breaks.

4. Rhetorical Moves (~200 words)

The 5-6 recurring moves I make: how I open, make asks, handle tension or pushback, use context or data, and close.

5. Emotional Register & Boundaries (~150 words)

Where warmth shows up. Where humor lives. What I'm earnest about. The line between professional and personal in my emails.

6. Do's and Don'ts (~200 words)

Specific, actionable rules with real examples from my emails. Focus on the mistakes someone would most likely make when imitating my voice.

7. Register Quick Reference (table)

One row per email type found in my corpus.

Columns: Email Type | Opening Move | Sentence Length | Tone | Signature Moves | Things to Avoid | Closing Style

8. Voice Calibration Tests

6 yes/no questions to check whether a draft sounds like me. Each should target a different dimension: structure, tone, specificity, point of view, authenticity, readability.

Output: Write in a direct, confident tone. Organize for quick reference, not start-to-finish reading.



Reusable prompt — merge voice guide into skill:

I just wrote my email voice guide. Add it to my humanize-writing skill:

1. Read the full contents of my email-voice-guide.md file.

2. Open the humanize-writing SKILL.md in ~/.claude/skills/

3. Find the "## Email Voice Guide" heading at the bottom. Replace the italic placeholder note under it with the full contents of my email voice guide. Leave the heading itself in place.

4. Don't change anything above that heading.

Save the updated skill.

Build 3 — Set up a scheduled email manager

Model: Sonnet · Time: 20 min

Build an email-manager skill that triages your inbox and drafts replies in your voice, then wrap it in a scheduled job that runs every weekday morning. Requires Build 2's voice guide and Build 1's Gmail connection to be complete.

Steps:

Open a new Claude Code session, set model to Sonnet, paste the email-manager build prompt — Claude Code interviews you first (always-ignore senders, always-reply senders, meeting-request/cold-outreach handling, what "urgent" means, etc.), then builds the skill from your answers.

Test by telling Claude Code "Run my email-manager skill."

Review: do drafts sound like you? right emails skipped? right things flagged urgent?

Give corrections and have Claude Code update the skill.

Set up the scheduled job (approve the exact command before it's added; confirm how to check/remove it later).

Reusable prompt — build email-manager skill:

Goal: I want to create a skill called "email-manager" that triages my inbox and drafts replies in my voice.

Here's the scaffolding:

- Read my humanize-writing skill before drafting anything

- Pull unread emails from the last 24 hours

- Skip noise: newsletters, automated notifications, CCs where I'm not expected to act

- Reply to: direct questions, decisions needed, relationship emails, time-sensitive items

- Draft replies for everything that needs one

- If you can make a reasonable decision for me, make it and note what you assumed

- If you're missing information, flag what you need

- Show urgent emails first, then everything else numbered

- Never send anything. Always show drafts for review.

Before you build this, interview me. Ask me about:

- What kinds of emails I always ignore

- Senders I always reply to right away

- How I handle meeting requests and cold outreach

- What "urgent" means to me

- Anything else that would help you triage smarter

Then build the skill based on my answers.



Reusable prompt — schedule the email manager:

Set up a scheduled task on my computer that runs my email-manager skill every weekday at 9am. Use headless mode (claude -p) and my computer's scheduler - cron if I'm on Mac or Linux, Task Scheduler on Windows. Before you make any changes, show me exactly what you're going to add and ask for my approval. After setting it up, tell me how to check it's scheduled and how to remove it later.



Go further: add a Slack manager (same pattern, scans unread Slack messages each morning and drafts short responses).

Build 4 — Scope your first custom workflow

Model: Sonnet · Time: 20 min

Identify a recurring task worth automating, define the workflow with Claude Code, and leave with a build-ready plan — without building it yet (saved for a future session).

Steps:

Browse example workflows by function (Sales, Marketing, Operations, Finance, Product/Design, Management, Content Creator, Personal) or use your own idea.

Post your chosen workflow (or idea) and its tools in the session chat.

Open a new Claude Code session and start scoping — Claude Code asks clarifying questions before building anything.

Answer follow-ups; explicitly keep Claude Code in planning mode (don't let it schedule the workflow yet).

Get a structured workflow summary and save it for a future build session.

Reusable prompt — start scoping:

Goal: I want to build a [workflow name] for my work.

Rules: Here's what I want it to do: [describe the output you want, who it goes to, and how often it should run]. Before you build anything, help me get more specific about the goal. What information do you need from me to make this useful?



Reusable prompt — keep Claude Code in planning mode:

Good. Now make a plan for how you'd build this. Show me: what tools it will connect to, what steps it takes, and what the final output will look like. Keep it simple enough to build in 20 minutes. Show me the plan before you build anything.



Reusable prompt — get workflow summary:

Summarize what we've decided so far in this format:

Workflow name:

What it does (one sentence):

Output: [what you receive, in what format]

Frequency / trigger:

Tools needed:

Ready to build: yes / needs [X] before we can start



Go further: practice on a messy folder first.
