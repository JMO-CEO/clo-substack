Terminal habit for this session

Claude Code keeps the whole session in memory until closed or /compact is run manually — there's no automatic background compression like the desktop app. Running /compact between heavy phases keeps the same important context at far fewer tokens, keeping sessions fast and costs lean. Build 1 — Craft an AI context file

Model: Sonnet · Time: 15 min

Give Claude Code persistent context — role, goals, rules, and preferences — via a CLAUDE.md file it reads automatically at the start of every session in the folder.

Steps:

Understand: CLAUDE.md lives at the root of ai-builder and is read automatically each session there.

Open a Claude Code session from inside ai-builder. Have it interview you one question at a time on: name and role, top goals this quarter, how you like AI to communicate, 2–3 always-follow rules, daily tools, where key files live, and anything else relevant. Have it draft the context with sections: About Me, Goals, How I Like AI to Respond, Rules, Tools, Key Files.

Review and edit the draft for accuracy, then have Claude Code save it to CLAUDE.md.

Test in a fresh session (Ctrl+C then claude again) by asking what it knows about you — it should reflect the context back.

Keep it current: the terminal doesn't auto-generate memory, so update CLAUDE.md whenever role, goals, or working style change ("Update my CLAUDE.md to reflect [what changed].").

Go further: keep building out your CLAUDE.md.

Build 2 — Create and add skills to upgrade your AI system

Model: Sonnet · Time: 20 min

Build, install, and activate 5–6 skills so Claude Code has repeatable workflows callable via a single slash command.

Steps:

In a new Claude Code session in ai-builder, ask AI to propose 5 skills based on your CLAUDE.md's repeatable workflows, existing folder contents/skills, and how you've used AI this program — ranked by weekly time saved.

Review the list, cross off anything that doesn't fit, and pick 1–3 to build now (more can come from marketplaces).

For each picked skill, have AI build and save it as a .skill file (slash-command-ready) with: a clear command name, step-by-step workflow instructions, examples drawn from your folder, and any rules for how you want it done. Build and save only — don't run or test yet.

Browse skills.sh and skillsmp.com for community-built skills; download useful .skill files into ai-builder — they become available as slash commands next session.

Verify: type / in the Claude Code session to confirm all skills are listed; troubleshoot any missing ones (check installed list, find the SKILL.md, flag errors, reinstall/recreate).

Run the skill you're most excited about on a real task; correct and refine the skill file based on the output — skills sharpen through correction, not careful first drafts.

Bonus build — /skill-doctor:

Goal: Build and save a /skill-doctor skill that audits my skills library and flags problems. Rules: When run, it should read every skill file in my ai-builder folder and flag skills with vague or generic instructions, skills that contradict each other, skills with no clear trigger, and skills I haven't used in 30+ days (check timestamps if available). Output as a table with skill name, issue, and suggested fix. Don't auto-fix anything, wait for my approval. Save as a .skill file in my ai-builder folder.



A skill that audits skills creates a feedback loop on the library itself — recommended to run monthly.

Go further: install skills from a marketplace.

Run /compact before Build 3.

Build 3 — Organize a folder

Model: Sonnet · Time: 15 min

Clean up the ai-builder folder so Claude Code has clear, structured context and everything is findable in seconds.

Steps:

Ask AI to audit the folder: contents grouped by type, duplicated/outdated files, bad naming conventions, files that belong in an archive, and obvious gaps — output as a table plus a summary of highest-impact changes. Don't make edits yet.

Review the plan, approve the right moves and push back on the rest, then have AI execute and show the new folder structure as a tree.

Have AI create a README.md (~200 words) explaining what the folder is for, its structure, and key files — for future-you, not a portfolio piece.

Go further: schedule a weekly folder audit.

Run /compact before Build 4.

Build 4 — Update your portfolio

Model: Sonnet · Time: 15 min

Fill in the three remaining Session-1 "Coming Soon" cards, write a program reflection, and publish the final portfolio.

Steps:

Ask AI to update the existing portfolio.html (not a new file), filling in all three remaining "Coming Soon" cards from Session 1: File Organization Process, AI Context File, and Skills Library — matching existing card design exactly, confirming no "Coming Soon" cards remain, and showing a diff before saving.

Ask AI to read everything in ai-builder (skills, drafts, voice guide, email manager, portfolio, context file) and write a 150-word reflection in your voice — covering what you built across the 4 sessions, what changed in how you work with AI, your strongest build, and what you'd build next — using the humanize-writing skill so it sounds like you.

Publish: upload the updated portfolio.html at builders.leland.ai (message a TA in Slack for the API key if needed).

Go further: write down your own principles.
