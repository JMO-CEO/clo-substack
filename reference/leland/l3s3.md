Build 1 — Identify what training your agents need

Model: Sonnet · Time: 15 min

Establish a real (predicted, not run) baseline per subagent, then diagnose every rough spot using the Sharp Test.

Steps:

Run the baseline-prediction prompt against a real task — it predicts what each subagent would produce today, purely from its current description, with no new skills/tools/MCPs assumed. Saves per-subagent predictions to audit/[subagent-name]-output.md and a combined audit/pipeline-output.md.

Run the gap-classification prompt to sort every rough spot into skill / tool-MCP / brain / disallow, without proposing fixes yet — saved to audit/gap-assessment.md.

Reusable prompt — predict baseline output:

Goal: For [the real task], go through my pipeline subagent by subagent and,

based only on each one's current description/system prompt (not a live

run), predict what it would actually produce at that step — not just the

final combined result.

Context: This is a baseline, so reason from exactly what each subagent's

description tells it to do today — don't assume a best case, and don't

add any new skills, tools, or MCPs first. I want to see where each

subagent, as written, would likely guess, improvise, or ask something it

should already know.

Rules: Create a audit/ folder. For each subagent, save your

prediction of its output to audit/[subagent-name]-output.md,

with a header naming the subagent, the task/input it would be given, the

date, and a line noting this is a predicted (not run) baseline. Then save

a predicted final assembled result to audit/pipeline-output.md,

with the same header plus a note that no training has been added yet.



Reusable prompt — classify gaps with the Sharp Test:

Goal: Audit the run in audit/ folder and classify every place

it guessed, improvised, asked me something it shouldn't have had to ask, or

already has access to something it shouldn't be trusted with yet.

Context: Use this test —

If it needs an explanation on tasks it should already know -> skill gap.

If it couldn't take an action it needs to complete -> tool/MCP gap.

If it is missing domain or company information -> brain gap.

If it can already do something — send, write, delete — that its job doesn't call for yet -> disallow gap.

Rules: For each issue you find, name the exact gap and which of the four

categories it falls into. For disallow findings, say whether it should be

removed from the subagent's tools entirely or kept but gated behind

approval. Don't guess at fixes yet, just diagnose. Save your findings to audit/gap-assessment.md.



Go further: get live results for the audit; turn the Sharp Test into a skill; build a baseline scorecard template.

Build 2 — Equip your agents with tools, skills, and MCPs

Model: Sonnet · Time: 20 min

Work through gap-assessment.md: find or build needed skills, wire them plus a tools allowlist into each subagent's frontmatter, connect MCPs/APIs, then run the first live (trained) test.

Steps:

For each skill gap, check whether an existing skill (in ~/.claude/skills/, .claude/skills/, or elsewhere) already covers it; migrate or build new one at a time via /skill-creator, reviewing each before moving to the next.

Update each subagent's frontmatter with the chosen skills: and a tools: allowlist, leaving out anything marked human-gated — review the diff before saving.

Connect each MCP/API from the gap assessment one at a time, scoped either inline to one subagent (mcpServers:) or at the project level (claude mcp add) if more than one subagent needs it.

Give a subagent a real task with training now in place, and review which skill/tool it used at each step.

Reusable prompt — find or build needed skills:

Goal: For each [skill] item in gap-assessment.md, check whether I already have

a skill elsewhere that covers it.

Context: Check ~/.claude/skills/, .claude/skills/, and anywhere else skills

might live.

Rules: For each item, say "migrate from [location]" or "build new." For new

ones, use /skill-creator to draft them one at a time — don't batch-write all

of them before I've reviewed the first.



Reusable prompt — wire skills + tools into frontmatter:

For each subagent, update its frontmatter: add the skills you

built or migrated for it under skills:, and set tools: to the allowlist you

decided — ask me first if I want to leave out anything marked human-gated in the

audit. Show me the updated file before saving.



Reusable prompt — connect an MCP/API:

I want to connect [MCP name] to [subagent name]. Check whether anything

needs to be installed locally first and handle it, or tell me how based on

my OS. Then connect it (inline in that subagent's mcpServers: field if only

that stage needs it, or at the project level with claude mcp add if more

than one subagent does), including any API key or OAuth step. Tell me

before you write anything.



Reusable prompt — first trained live run:

Give [subagent] a real task you'd actually hand it. Show me which

skill and tool it used at each step, not just the final output.



Go further: audit MCP tool descriptions; build a custom MCP server.

Build 3 — Build a shared brain for your agents

Model: Sonnet · Time: 15 min

Scaffold a wiki folder — separate from any single agent — that every agent and subagent reads from and writes to, on the LLM Wiki raw/ → pages/ pattern.

Steps:

Create a new folder outside the agents folder for the shared brain.

Point the AI tool at the empty folder and run the scaffold prompt to create CLAUDE.md, index.md, log.md, raw/, pages/.

Ingest a first source (company website, portfolio, pitch deck, product page, ICP doc, resume, meeting notes) via the ingest prompt — the agent asks 1–2 clarifying questions about which facts/angles matter before writing pages, then documents that focus as a new rule in CLAUDE.md for future ingestions.

Reusable prompt — scaffold the shared brain:

This folder is my shared brain, used by multiple agents. Set it up with the following LLM Wiki pattern:

├── CLAUDE.md - Describes how a page is structured (title, sumary, key fact, links) how pages cross-link with [[double-bracket links]], and the rule that every claim on a page traces to a file in raw/

├── index.md - Set this up as a content-oriented catalog where every page in the wiki will be listed with a link, a one-line summary, and metadata

├── log.md - Set this up as a chronological, append-only record to track every ingest, query, and lint pass

├── raw/ - This will hold my untouched, immutable source documents like PDFs and notes

└── pages/ - This is where you will write and maintain the Wikipedia-style concept pages and entities



Reusable prompt — ingest first source:

Ingest [this file or URL] into my shared brain following the CLAUDE.md, but before you write any pages ask me 1 or 2 questions about what specific facts or angles are most important to pull from this for my pipeline's goals. Once I answer, compile the wiki pages focusing on what we discussed. Finally, update our schema file (CLAUDE.md) with a new rule documenting the angles I told you to focus on, so you automatically apply them to future ingestions.



Go further: import an existing notes system; add a people/projects taxonomy; draft a deletion policy.

Build 4 — Build up your shared brain

Model: Sonnet · Time: 15 min

Pull in more raw sources, complete the ingest into pages, run a manual lint pass, and teach the agent the ingest/lint workflow so it doesn't need re-explaining.

Steps:

Have the agent pull raw material from connected tools and the working directory into raw/ (capped at 5–6 sources, prioritizing the last 1–2 weeks).

Ingest those raw files into structured pages/, updating index.md and merging with existing pages where appropriate.

Run a manual lint pass: scan pages/ for orphan pages, contradictions, and stale claims — fix unambiguous issues, flag uncertain ones.

Add a "standard workflow" section to CLAUDE.md explicitly defining the ingest and lint workflows, so future requests don't need re-explaining.

Reusable prompt — pull sources into raw/:

Goal: Pull raw source material from my connected tools and working directory into [shared-brain-folder]/raw/.

Context: Focus on recent meeting notes, project docs, team intros, role descriptions, planning docs, and anything that names the people I work with or the projects I own. To keep this fast, pull from no more than 5-6 sources total, prioritizing anything from the last 1-2 weeks.

Rules:

- Save each source as a .md file in [shared-brain-folder]/raw/ with a slugified filename (a copy, or a clear summary with a link back to the original)

- Include a Source: line at the top of each file with where it came from and the date

- Don't filter or interpret yet, capture wide

- When done, list what you added



Reusable prompt — ingest raw into pages:

Goal: Read the files I just added to raw/ and create ingest them into pages.

Context: Follow the ingest instructions and pages description defined in CLAUDE.md.

Rules:

- Update [shared-brain-folder]/index.md with a one-line description of each new article under the right type heading

- Merge and synthesize data existing pages if appropriate



Reusable prompt — manual lint pass:

run a lint pass: check for contradictions between articles, claims that reference outdated facts, and orphaned files nothing links to. Report what you find and fix anything unambiguous. Flag anything uncertain instead of guessing.



Reusable prompt — document the workflows in CLAUDE.md:

In our CLAUDE.md update our file by adding a 'standard workflow' section that explicitly defines the Ingest workflow and lint workflow we just completed.

We want to be able to ask to ingest or lint in the future without having to explain what that means



Go further: do a full ingest sweep; build a weekly digest.

Build 5 — Make the brain compound on its own

Model: Sonnet · Time: 15 min

Automate proactive ("dream cycle") ingest and lint on a weekly cadence, register the brain's path in the main orchestrator, and add reactive logging so new facts get captured the moment a subagent finishes a task.

Steps:

Set up a weekly scheduled routine that scans connected meeting notes, Slack, and calendar for anything worth adding to the wiki, filing it per the schema and citing the source.

Set up a second weekly scheduled routine that runs the lint pass to catch drift before it compounds.

Switch back to the main agent folder in Claude Code.

Register the shared brain's path in the orchestrator's CLAUDE.md so it knows to read from and write to it.

Add a rule so subagents never write to the brain directly — logging happens at the orchestrator level the moment a subagent returns a completed task.

Reusable prompt — automate proactive ingest:

On a weekly cadence, check my connected meeting notes, Slack, and calendar for anything from the last period worth adding to the wiki, a decision, a correction, a new fact about a person, project, or anything that is related to the pages I have in my shared-brain. File it following the existing (CLAUDE.md) schema, cite the source, and skip anything routine. Log what you added and what you skipped.



Reusable prompt — automate lint:

On a weekly cadence, open the shared wiki and run a lint pass: check for contradictions between articles, claims that reference outdated facts, and orphaned files nothing links to. Report what you find and fix anything unambiguous. Flag anything uncertain instead of guessing.



Reusable prompt — register the brain in the orchestrator:

My shared brain folder is called [shared-brain-folder name]. Find its full path on this machine, then add a line to my CLAUDE.md recording that path and noting this agent should read from and write to it.



Reusable prompt — reactive logging at the orchestrator:

Every time a subagent returns a completed task, evaluate the result. If it contains a new fact, correction, or pattern, synthesize it into the pages/ folder and append it to log.md



Go further: visualize the brain; build a Slack/email digest bot.
